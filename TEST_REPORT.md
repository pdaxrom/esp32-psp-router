# Отчёт о проверках релиза 1.0.0

Дата: **7 ноября 2026**, Asia/Yerevan.

Реализован согласованный **L2 bridge USB ↔ Wi-Fi AP с одной подсетью**.
DHCP/DNS и маршрутизацию в интернет обеспечивает компьютер. Первоначальные NAPT,
собственный DHCP-сервер ESP и разные подсети заменены этим уточнением пользователя.

## Результат

Пользователь подтвердил работу PSP на финальном ECM-релизе после проверки
получения IP/DNS и открытия HTTP-сайта. Обнаружена причина прежнего таймаута:
в ARK-5 была включена опция **WPA2 Support**. После её отключения WPA1/TKIP
заработал. Инструкция добавлена в README. В WPA2-патче ARK действительно
[меняется EAPOL на RSN/WPA2](https://github.com/PSP-Archive/ARK-4/blob/main/core/compat/psp/wpa2.c).

Релиз не содержит WPA-трассировки, сниффера, самопроверки HMAC, USB CDC-консоли,
периодического статуса, счётчиков отладки и временного автоматического входа
в ROM. Принудительные 1 Мбит/с удалены; драйвер выбирает скорость в пределах
802.11b. WPA1/TKIP, EAPOL v1, видимый PSP-NET, канал 6 и пароль psp3000wifi сохранены.
Защита на открытую сеть автоматически не меняется.

между своими esp_wifi/wpa_supplicant; исходники установленного IDF не изменялись.
Локальные тесты не эмулируют USB хоста, радио или PSP.

## Выполненные аппаратные проверки

- ROM определил ESP32-S3 QFN56 rev 0.2, Flash **4MB XMC**, PSRAM **2MB AP_3v3**;
  flash-id **20:4016**, quad/3.3V. Диагностический образ измерил
  Flash=4194304 и PSRAM=2097152. Проверки памяти сохранены в релизе.
- Восстановление через native USB **BOOT/RESET** использовано при прошивках.
  Secure Boot/Flash Encryption/eFuse, закрывающие восстановление, не включались.
- Финальный ECM-релиз записан вместе с bootloader и partition table;
  esptool подтвердил хэши всех записанных областей: `dist/flash-ecm-release.log`.
- macOS 27.2 распознала ECM штатным драйвером: **en13**, MAC **d2:cf:13:30:15:cd**,
  status active. После удаления CDC последовательный порт отсутствует ожидаемо.
- Internet Sharing: **bridge100=192.168.2.1/24**, участник en13;
  ESP получил **192.168.2.4**, шлюз/DNS **192.168.2.1**.
- После прошивки релиза ESP ответил на **3/3 ICMP**, потерь 0%, среднее 1.555 мс.
- Компьютер выдал PSP аренду **192.168.2.5** для **00:23:4e:17:88:02**.
  Исходный MAC PSP виден на bridge100 в ARP — прозрачность L2 подтверждена.
- Пользователь подтвердил работу **финального релиза** после проверки IP/DNS/HTTP
  с выключенным WPA2 Support в ARK-5.

В macOS 27 обычный ifconfig может скрывать MAC за 02:00:00:00:00:00.
Пользователь подтвердил настоящий MAC через sudo ifconfig;
[Apple описывает ограничение](https://developer.apple.com/forums/thread/841958).
Это не MAC, записанный в USB-дескриптор ESP.

## Проверки, требующие отдельного аппаратного прогона

| Проверка | Статус |
| --- | --- |
| Windows RNDIS и ICS | Не выполнено; сборка/дескрипторы проверены |
| Ubuntu ECM и NetworkManager shared | Не выполнено |
| Потеря upstream на 60 с и восстановление новых HTTP/DNS-запросов PSP | Не выполнено |
| Не менее 20 циклов USB unplug/reset/suspend/resume | Не выполнено; повторные перечисления при прошивках не заменяют этот тест |
| Смена подсети общего доступа с обновлением DHCP PSP | Не выполнено |
| Неверный ключ, явно выбранный OPEN и возврат к WPA1 | Код/сборки проверены, аппаратно не выполнено |
| Минимум час передачи с PSP, без зависаний/утечек | Не выполнено |

Физическое отключение единственного USB-кабеля отключает питание. Холодный старт
и тёплый reset/suspend проверяются отдельно. Старые TCP-сеансы могут закрыться;
критерий восстановления — успешные новые запросы.
