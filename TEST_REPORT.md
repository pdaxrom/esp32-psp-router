# PSP Router 2.0 — отчёт о проверках

Обновлено: **8 ноября 2026**, Asia/Yerevan; измерения 2.0.0 ниже — от 7 ноября.

## Текущий статус

Реализован вариант 2: USB — отдельный WAN с DHCP-клиентом; Wi-Fi — собственный
LAN с DHCP, UDP DNS relay и IPv4 NAPT. Дополнительно работает ограниченный
HTTP→HTTPS шлюз для старого браузера PSP, полностью на ESP32-S3.

**Текущий образ ECM/WPA1/router 2.0.1 прошит и проверен на ESP32-S3 через USB-компьютер.**
WAN получил 192.168.2.6/24, шлюз/DNS 192.168.2.1; LAN — 192.168.50.1/24.
Пройдены аппаратные проверки DNS, HTTPS, отрицательные проверки сертификатов,
переписывание HTML/редиректов, два параллельных запроса и три загрузки по 64 КиБ.
Пользователь подтвердил работу браузера PSP через прокси на ya.ru и, после
обновления 2.0.1, на zond.am и pdaxrom.org. Страницы открываются, современная
вёрстка отображается некорректно; адаптация HTML/CSS не реализована.
Прямой NAT без прокси, переподключение USB и потеря upstream ещё не проверены.

## Исправление 2.0.1: перекрёстно подписанные CA

На установленном образе 2.0.0 воспроизведено:

| Адрес | Компьютер, TLS 1.2 с тем же cacrt_all.pem IDF | ESP 2.0.0 |
| --- | --- | --- |
| zond.am | 200 | 502, Unable to establish upstream HTTPS connection |
| pdaxrom.org | 301 на https://www.pdaXrom.org/ | 301, Location переписан в HTTP |
| www.pdaxrom.org | 200 | 502, та же ошибка |

Серверы zond.am и www.pdaxrom.org передают цепочку WE1 → GTS Root R4,
содержащую перекрёстную подпись от GlobalSign Root CA. Корень GTS Root R4 есть
в полном bundle IDF. В 2.0.0 отключена опция
`CONFIG_MBEDTLS_CERTIFICATE_BUNDLE_CROSS_SIGNED_VERIFY`; совпадающий случай
описан в [issue Espressif #18674](https://github.com/espressif/esp-idf/issues/18674).
В 2.0.1 включена эта штатная опция и добавлена её обязательная проверка в
`tools/check_build.py`. Имя, срок и доверие сертификата продолжают проверяться.
IDF/managed-компоненты не изменялись.

**2.0.1 собран и прошит в ECM/WPA1/router.** Esptool 5.6.0 проверил хэши
bootloader/partition/app и завершился кодом 0; USB WAN снова получил 192.168.2.6,
страница состояния доступна, часы синхронизированы. Полный live-прогон **PASS**:

| www.pdaxrom.org | 200, 48285 байт |

| Три загрузки 64 КиБ | 4,287 / 4,303 / 4,187 с; 14,87–15,29 КиБ/с |

Условия замера те же, что для 2.0.0 ниже. DNS/TCP/TLS на ESP заняли
2862 / 2851 / 2811 мс. Журналы — `dist/flash-router-v2.0.1.log`,
`dist/router-live-2.0.1.log`; результаты — `dist/router-live-2.0.1.json`.
Пользователь подтвердил открытие обоих адресов непосредственно в браузере PSP
после обновления. Отмечено некорректное отображение оформления.

Дополнительная проверка через ESP: у обоих сайтов внешняя таблица
`/css/all.min.css` загружается с HTTP 200, Content-Type text/css, 58576 байт.
Встроенные стили содержат Flexbox, Grid, CSS custom properties/var(), media

всех ресурсов браузером PSP. Данные — `dist/psp-css-check.json`.

Данные воспроизведения — `dist/tls-cross-signed-before.json`; live-тест расширен
повторяемым параметром `--site` для проверки этих адресов после прошивки.

Собраны и проверены `tools/check_build.py` оба релиза 2.0.1: ECM/WPA1/router —
810224 байта приложения; RNDIS/WPA1/router — 810160 байт. Open/bridge в 2.0.1
повторно не собирались; результаты их сборок ниже относятся к 2.0.0.

Рабочий bridge 1.0.0 сохранён в коммите 692b7ec и
`dist/psp-bridge-ecm-v1.0.0.bin`. Его аппаратная проверка IP/DNS/HTTP с PSP и

## Зафиксированная среда

ESP-IDF v6.1-dev-4811-gfce70533fa, commit
`fce70533fa1fdeef9f903ce5e87ff8d292be992b`; GCC 15.2.0;
esp_tinyusb **2.0.1~1**, tinyusb **0.21.0~4**, registry-хэши в dependencies.lock.
HTTP/TLS/SNTP/NAPT — из этой же IDF, новых внешних зависимостей нет.

Сборка 2.0.1 использует уже установленную Python 3.15.2 среду IDF:
Component Manager 3.1.2, esp-idf-kconfig 3.14.0, esp-idf-monitor 1.10.0,
esptool 5.6.0. Прежняя среда Python 3.14 не удовлетворяет обновлённому файлу
constraints; CMake перепривязан к текущей среде. Ревизия IDF и версии двух
managed-компонентов сохранены.

Router: CPU 240 МГц, Flash 4 МиБ QIO/80 МГц, PSRAM Quad/40 МГц, 2 МиБ.
Крупные TLS-буферы используют штатный malloc с PSRAM; AES/SHA/MPI ускорение
включено. Стартовая проверка физических Flash/PSRAM и ROM BOOT/RESET сохранены.
Логирование, USB-консоль и сниффер не включены; WPA1/TKIP и EAPOL v1 сохранены.

При прошивке 2.0.0 esptool завершился кодом 1: после проверки записанных хэшей watchdog уже
перезапустил USB, а завершающий serial ioctl получил Device error. Приложение

`dist/flash-router-v2.log`, хэш записанного приложения —
`dist/flashed-ecm-app.sha256`.

ESP-TLS в этой сборке возвращает для проверенных неверных сертификатов общее
сообщение об ошибке HTTPS без детальных X.509 flags. Первый вариант live-теста
ошибочно требовал конкретный текст сообщения. Тест уточнён: корректный
сертификат на том же сервисе должен дать 200, три неверных — 502. Обхода проверки
сертификатов или изменений прошивки для этого не было.

### Измерение HTTPS на ESP

Цель — `https://httpbingo.org/bytes/65536`, клиент — USB-компьютер. Каждый запрос
создаёт новое HTTPS-соединение; измеряется весь путь через ESP, включая upstream
компьютера и возврат данных тому же USB-компьютеру.

| Прогон | DNS/TCP/TLS, ESP | Всего, ESP | Всего, клиент | Скорость всего |
| --- | --- | --- | --- | --- |
| 1 | 2900 мс | 4252 мс | 4,263 с | 15,01 КиБ/с |
| 2 | 2932 мс | 4284 мс | 4,294 с | 14,91 КиБ/с |
| 3 | 2913 мс | 4310 мс | 4,319 с | 14,82 КиБ/с |

Это подтверждает работоспособность TLS на плате для простых страниц. Эти числа
не являются чистой скоростью шифрования или измерением радио/браузера PSP.
Машиночитаемые результаты — `dist/router-live.json`, полный вывод —
`dist/router-live.log`.

Для аппаратного прогона с USB-компьютера, после получения WAN-адреса ESP:

```sh
python tools/test_router_live.py WAN_IP_ESP --report dist/router-live.json
# Регрессия перекрёстных CA:
python tools/test_router_live.py WAN_IP_ESP \
  --site zond.am --site pdaxrom.org --site www.pdaxrom.org \
  --report dist/router-live-2.0.1.json
```

Скрипт проверяет время, DNS, HTTPS, отклонение недействительного сертификата,
CONNECT, два параллельных запроса и три загрузки по 64 КиБ. Connection включает
DNS/TCP/TLS; Total дополнительно включает сервер и доставку USB-клиенту. Это не
изолированный криптобенчмарк и не измерение скорости радио PSP.

Ограничения шлюза: GET/HEAD, публичные страницы без cookies/авторизации/POST;
нет серверного рендеринга JS/конвертации WebP/видео. DNS relay — UDP до 1232 байт,
без TCP. Никакого автоматического отключения защиты Wi-Fi или TLS-проверки нет.
