# Bridge/WPA2 2.1.3 — аппаратная проверка

Дата: **8 ноября 2026**, Asia/Yerevan.

## Текущее состояние

**Пользователь подтвердил подключение PSP, локальную страницу компьютера и
прямое открытие example.com по HTTP без proxy. Работа после переподключения
USB подтверждена свежим HTTP-запросом на новый порт.**

На плату записан **ECM / WPA2 / bridge 2.1.3**. esptool проверил хэши
bootloader, partition table и приложения и завершился кодом 0.
Лог: `dist/flash-bridge-ecm-wpa2-v2.1.3.log`.
Приложение: 600208 байт, SHA-256 `b3e9001f532da6f5f254a2b3f1293c7b8e04a5325f32ed1863049d51638555c1`.
Рабочий router 2.1.3 сохранён отдельно; его аппаратная приёмка не относится
автоматически к текущему bridge-тесту.

SSID PSP-NET, WPA2-PSK / AES-CCMP, EAPOL v2, PMF выключен, 802.11b, канал 6.
IP/DNS выдаёт компьютер; ESP не запускает NAPT, DHCP-сервер или browser proxy.
Конфигурация Flash 4 МиБ, Quad PSRAM 2 МиБ, CPU 160 МГц; зависимости и IDF
те же, что в [основном отчёте](../TEST_REPORT.md).

## Выполнено

- Все четыре bridge-сборки ECM/RNDIS × WPA1/WPA2 прошли сборку и ELF/config checks.
- Проверены SHA-256 объединённого ECM/WPA2 образа и точное совпадение приложения.
- Запись с проверкой хэшей — PASS; NVS при компонентной прошивке не стиралась.
- macOS повторно распознала USB ECM как en13, status active.
- Internet Sharing: bridge100=192.168.2.1/24, участник en13.
- ESP получила адрес **192.168.2.4** от DHCP компьютера, MAC d0:cf:13:30:15:4d.
- Ping ESP с компьютера — **3/3**, потерь нет, среднее 2,046 мс.
- Для проверки PSP временно запущена HTTP-страница компьютера
  **http://192.168.2.1:8080/**. Локальный контроль компьютером — HTTP 200.
  Сценарий: `/private/tmp/psp_bridge_http_test.py`, журнал
  `dist/bridge-wpa2-host-http.log`. В нём фиксируется IP клиента без proxy/NAT.
- Компьютер принял **4 HTTP 200 от 192.168.2.5**; это адрес PSP, а не ESP.
- На bridge100 виден исходный MAC PSP **00:23:4e:17:88:02** для 192.168.2.5;
  L2-прозрачность и одна подсеть подтверждены.
- Компьютер получил HTTP 200 без редиректа от example.com, captive.apple.com
  и detectportal.firefox.com. Это контроль upstream, не результат с PSP.

## Проверки с PSP

- [x] WPA2/AES подключение с WPA2 Support в ARK-5.
- [x] IP/DNS автоматически от компьютера в 192.168.2.0/24, proxy выключен.
- [x] Открытие тестовой страницы компьютера; IP HTTP-клиента отличается от IP ESP.
- [x] Прямой HTTP в интернет: http://example.com/.
- [x] Новое подключение после переподключения USB.

После USB пользователь сообщил, что страницы работают. Для независимой
проверки свежего запроса запущен новый временный адрес
**http://192.168.2.1:8081/**: в журнале 8080 не появилось нового запроса после
USB, поэтому сохранённая страница не считалась доказательством HTTP-доставки.
ESP после переподключения отвечает **3/3 ICMP**, среднее 2,031 мс.
PSP в тот момент не ответила на 3 ICMP; причина не установлена, один ping
не использовался как доказательство отказа браузера. Затем компьютер принял
**новый GET от 192.168.2.5 на порт 8081 и ответил HTTP 200**. Пользователь
подтвердил отображение страницы. Это независимая проверка свежей передачи
после USB, а не повторное отображение ранее сохранённой страницы.
Журнал — `dist/bridge-wpa2-host-http-after-usb.log`.
Оба временных HTTP-сервера компьютера после проверки остановлены;
адреса 192.168.2.1:8080 и :8081 не являются сервисами прошивки.

Bridge не предоставляет HTTP→HTTPS адаптацию браузера.

Проверенный полный образ — `dist/psp-bridge-ecm-wpa2-v2.1.3.bin`, offset 0x0,
665744 байта, SHA-256
`988f1cf4329776cac4ffd602e43efb2cf164f3ef8dfcd7678e5eff39cdbb5ced`.
Manifest вариантов — `dist/bridge-v2.1.3-manifest.json`.
