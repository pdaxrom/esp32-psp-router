# PSP Router

[English](README.md)

Прошивка ESP-IDF для **Super Mini ESP32-S3 HW-747**: компьютер раздаёт интернет
через USB, а ESP передаёт его PSP по Wi-Fi. Дополнительные аппаратные модули не нужны.
Плата: **ESP32-S3FH4R2, 4 МБ Flash, 2 МБ QSPI PSRAM**; native USB-C использует
GPIO19 (D−) и GPIO20 (D+). Перед запуском Wi-Fi прошивка проверяет размер памяти.

## Режимы

| Режим сборки | Сеть | Прокси для браузера PSP |
| --- | --- | --- |
| `router` | USB WAN получает DHCP от компьютера; Wi-Fi — отдельная подсеть с DHCP, DNS и NAT. | По умолчанию `192.168.50.1:8080` |
| `bridge` | Компьютер выдаёт ESP и PSP адреса в одной подсети. | Нет |
| `bridge-proxy` | Тот же прозрачный мост с HTTP→HTTPS шлюзом. | `psp-proxy:8080` |

В режиме router LAN по умолчанию — `192.168.50.0/24`; при пересечении с USB-подсетью
она меняется. В таком случае адрес прокси — шлюз, полученный PSP.
В bridge-proxy ESP разрешает имя `psp-proxy` для Wi-Fi-клиентов в свой текущий
DHCP-адрес. Имя вводится без `http://` и `.local`; на компьютере оно может не разрешаться.

## Сборка

Закреплённые зависимости:

- ESP-IDF **v6.1-dev-4811-gfce70533fa**, коммит `fce70533fa1fdeef9f903ce5e87ff8d292be992b`.
- `espressif/esp_tinyusb` **2.0.1~1** и `espressif/tinyusb` **0.21.0~4**.

Версии проверяют CMake, [idf_component.yml](main/idf_component.yml)
и [dependencies.lock](dependencies.lock).

```sh
. "$HOME/Work/ESP/esp-idf/export.sh"
sh tools/build.sh ecm wpa2 bridge-proxy  # macOS/Linux, мост + прокси
sh tools/build.sh rndis wpa2 bridge-proxy # Windows, мост + прокси
sh tools/build.sh ecm wpa2 router        # отдельные WAN/LAN + NAT + прокси
sh tools/build.sh ecm wpa1 bridge        # мост для штатной прошивки PSP
```

Аргументы: `[ecm|rndis] [wpa2|wpa1|open] [router|bridge|bridge-proxy]`.
По умолчанию: `rndis wpa2 router`. Каждая комбинация собирается в отдельный
каталог `build-<usb>-<security>-<mode>`. Вариант `open` явно включает открытую
диагностическую сеть; автоматического переключения защиты нет.

Для изменения пароля, порта прокси или RGB откройте раздел **PSP USB router**:

```sh
idf.py -B build-ecm-wpa2-bridge-proxy \
  -DSDKCONFIG=build-ecm-wpa2-bridge-proxy/sdkconfig menuconfig
```

## Прошивка и восстановление

1. Подключите native USB-C кабелем с передачей данных.
2. Зажмите **BOOT**, нажмите и отпустите **RESET**, затем отпустите **BOOT**.
3. Прошейте выбранную сборку, подставив порт ROM-загрузчика:

   ```sh
   idf.py -B build-ecm-wpa2-bridge-proxy \
     -DSDKCONFIG=build-ecm-wpa2-bridge-proxy/sdkconfig \
     -p /dev/cu.usbmodemXXXX flash
   ```

4. Если приложение не запустилось автоматически, нажмите **RESET** без BOOT.

В Windows используйте соответствующий каталог сборки и порт `COMx`. Во время
обычной работы USB определяется как сетевая карта, без последовательной консоли.
Восстановление через BOOT/RESET сохраняется. `idf.py flash` сохраняет NVS;
отдельный бинарник приложения записывается по `0x10000`, а не `0x0`.

## Общий доступ компьютера

У компьютера должно быть отдельное подключение к интернету. Раздавайте его
**на USB-адаптер ESP**:

- **Windows / RNDIS:** откройте `ncpa.cpl`, затем свойства интернет-адаптера →
  «Доступ». Разрешите общий доступ и выберите RNDIS-адаптер ESP.
  Используется штатный драйвер Remote NDIS.
- **macOS / ECM:** «Настройки системы → Основные → Общий доступ → Общий интернет».
  Выберите источник интернета и USB Ethernet ESP как получателя.
  Точку доступа Wi-Fi создаёт сама ESP.
- **Ubuntu / ECM:** в NetworkManager для USB Ethernet выберите метод IPv4
  **Shared to other computers**. Внешнее подключение к интернету оставьте включённым.

В режимах bridge компьютер также выдаёт PSP адрес, шлюз и DNS напрямую.

## Подключение PSP

Wi-Fi: **PSP-NET**, пароль **psp3000wifi**, 2,4 ГГц / 802.11b / канал 6.

1. Для **WPA2** включите **WPA2 Support** в ARK-5, полностью выключите и включите
   PSP, затем создайте подключение с **AES** (в меню может называться WPA-PSK (AES)).
   Для **WPA1** используйте сборку `wpa1` и **TKIP**; выключите WPA2 Support в ARK-5
   и перезапустите PSP. WPA1 подходит для штатной прошивки Sony.
2. IP и DNS — **автоматически**.
3. Для прямого доступа выберите **Proxy → Do Not Use**. Для браузерного шлюза —
   **Use**, затем адрес и порт из таблицы режимов.
4. Откройте `http://psp-proxy:8080/` в bridge-proxy или
   `http://192.168.50.1:8080/` при стандартной конфигурации router.

Адреса сайтов вводите с **http://**, например `http://zond.am/`. ESP обращается
к сайту по HTTPS и проверяет сертификат; PSP получает HTTP по защищённому Wi-Fi.
После запуска дождитесь синхронизации времени ESP.

Шлюз рассчитан на простые публичные страницы: GET/HEAD, два одновременных запроса,
до 4 МиБ на ответ. Современные CSS/JavaScript, авторизация и видео не адаптируются,
POST и CONNECT не поддерживаются. Сайты только с HTTP открывайте без прокси.

## RGB-индикация

Встроенный RGB подключён к GPIO48. Яркость и отключение доступны в `menuconfig`.

| Индикация | Значение |
| --- | --- |
| Красный | USB-сеть не активна |
| Жёлтый | USB активен, интернет ещё не подтверждён |
| Зелёный | Успешна внешняя HTTP-проверка доступности интернета |
| Короткий голубой импульс каждые 2 секунды | Подключён Wi-Fi-клиент; между импульсами виден основной цвет |

Проверка интернета выполняется в фоне; изменение может отобразиться примерно
через 30 секунд. Отдельный синий индикатор зарядки может мигать без аккумулятора.

## Разработка

`tools/build.sh` проверяет конфигурацию прошивки и USB-дескрипторы.
Тесты на компьютере: `sh tools/test_host.sh`. Результаты сборки и локальные
отчёты о тестировании исключены из Git.
